# tests/fuzz — cargo-fuzz targets

This directory is **excluded** from the Cargo workspace (`exclude = ["tests/fuzz", ...]` in the root
`Cargo.toml`) and is a standalone cargo-fuzz project (`Cargo.toml` here, targets in `fuzz_targets/`).

## Running (inside WSL2, nightly)

```bash
cargo +nightly fuzz run --fuzz-dir tests/fuzz --target x86_64-unknown-linux-gnu directives_grammar -- -max_total_time=60
cargo +nightly fuzz run --fuzz-dir tests/fuzz --target x86_64-unknown-linux-gnu fuzz_automata_scan -- -max_total_time=60
cargo +nightly fuzz run --fuzz-dir tests/fuzz --target x86_64-unknown-linux-gnu fuzz_automata_user_regex -- -max_total_time=60
wsl -d Ubuntu-24.04 -- bash @prime/tools/setup/verify-proofs.sh 60    # every target + Miri + Kani
```

Always pass `--target x86_64-unknown-linux-gnu`: cargo-fuzz defaults to the triple its own binary was
built for, and the cargo-binstall build is musl (PLAN W20). `corpus/`, `artifacts/` and `coverage/` are
git-ignored; a crash is turned into a regular unit test in the owning crate.

## Why it is separate

- `cargo fuzz` needs a nightly toolchain and libFuzzer instrumentation; ASan/libFuzzer on
  `x86_64-pc-windows-msvc` is unreliable, so fuzzing runs **inside WSL2 (Ubuntu 24.04) on nightly**.
- An excluded manifest cannot inherit `version.workspace` / `lints.workspace`; its `Cargo.toml` uses
  literal values. `libfuzzer-sys` lives only here (not in `[workspace.dependencies]`).
- The `fuzz_target!` macro expands to `unsafe` FFI glue: this is a declared, signed-off exception to the
  zero-`unsafe` rule (see `@prime/PLAN.md` → ADR "Unsafe policy").

Each target asserts **no panic** plus a round-trip or invariant property (e.g. `unmask(mask(x)) == x`,
`expand(fold(x)) == x` byte-for-byte).

Current P1 evidence and exact limits: [P1_LOGIC_STATUS.md](../../@prime/P1_LOGIC_STATUS.md).
Additional P1 targets: `bus_ops`, `registry_fts_query`, `registry_migration_open`,
`code_intel_parse`, `code_intel_skeleton`, `code_intel_merge3`. They use real adapters or explicitly
labeled test-only models, and enforce bounded inputs. The mandatory six run in `verify-p1-fuzz.sh`;
registry/code-intel/bus runners retain separate raw logs.

Automata 60-second runs are recorded in `@prime/tmp/p2/automata-scan-fuzz-60s.txt` and
`@prime/tmp/p2/automata-user-regex-fuzz-60s.txt`; Kani, Miri, and dense-versus-hybrid measurements
are recorded beside them when executed. These are bounded discovery runs, not a proof of absence of
bugs or a claim that the bypass corpus is complete.
