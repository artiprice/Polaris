## Findings that change the plan

1. **No mTLS in the SDK's `ClientConfig` (VERIFIED, source at rev 5a7728c3).** Polaris builds the tonic
   channel itself — `ClientTlsConfig` with the gateway CA, client `Identity` (tls.crt + tls.key) and
   `domain_name("localhost")` — then calls `OpenShellClient::from_parts(channel, EdgeAuthInterceptor::noop())`.
2. **Dial `localhost`, not `127.0.0.1`, from Windows (VERIFIED).** The gateway binds `127.0.0.1:17670` inside
   WSL2; WSL's localhost forwarding answers on `localhost` from Windows. Certificate SANs cover
   `localhost`, `127.0.0.1`, `::1`.
3. **Certificates are per PC (VERIFIED).** `\\wsl.localhost\Ubuntu-24.04\home\dev\.config\openshell\gateways\openshell\mtls\{ca.crt,tls.crt,tls.key}`;
   generated by each member's gateway, read at connect time, never copied into the repo.
4. **Request size limit 1 MiB (VERIFIED in S0-7).** The gateway rejects decoded requests above
   1,048,576 bytes (`OutOfRange`), so any stdin payload through `ExecSandbox` must be chunked (S0-7 uses 896 KiB).
5. **Cold start (VERIFIED 2026-10-20 21:31).** After the WSL2 distro boots, the gateway needs ~3 s before it
   listens (`systemctl` already reports `active`); the client must retry connect with backoff (`backon`).
6. **Idle shutdown (pitfall W14, VERIFIED).** WSL2 stops an idle distro, taking the gateway with it — keepalive
   per PC (`setup-windows.ps1 -RegisterKeepalive`) plus reconnect logic in `polaris-openshell-client`.

## Consequences

- `polaris-openshell-client` owns channel construction (mTLS identity, `localhost`, retry/backoff, 1 MiB chunking).
- `polaris-platform-wsl` locates the certificates and keeps the distro alive.
- Conditions: Windows 11 LTSC 2024; rustc 1.99.0; gateway 0.1.4 in Ubuntu 24.04.5, docker driver (Docker Engine 29.9.1).
